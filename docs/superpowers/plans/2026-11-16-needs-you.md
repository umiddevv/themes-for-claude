# Needs you Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Needs you" side pane in themes-for-claude. It ranks what needs the
person across connected apps and Claude sessions, in the Pomodoro widget style.

**Architecture:**
- Pure logic lives in `needs-core.ts`, SVG drawing in `needs-card.ts`, and MCP
  fetching in `needs-sources.ts`.
- `needs.tsx` owns the atoms, the store, the clock, the `/needs` command, the
  pane, and the per-session state reporter.
- Fetchers return raw text from each source's MCP tool. One
  `$.model.complete({ model: 'haiku' })` call turns all that text into ranked
  items, so no per-source parsing is needed.

**Tech Stack:** Claude Code function-hook mod (TSX), `claude plugin test`, `tsc`.

**Spec:** `docs/superpowers/specs/2026-11-16-needs-you-design.md`

## Global Constraints

- Levels:
  - `now`: a person waiting on you, something due today, or a meeting within
    30 min.
  - `today`: questions, reviews, unanswered invites, or a Claude session
    waiting.
  - `hidden`: newsletters, promos, automated notifications, or threads you
    already answered.
- At most 7 items are shown. Snooze lasts 1 hour. The check interval is 15
  minutes by default.
- Only one session checks per round. The claim is kept in the store under
  `needs-lease`.
- The model is called only when the source text changed since the last check
  (compared by hash).
- Atoms are declared in the file that reads them. `$` is passed only to named
  top-level or imported functions.
- The card is drawn as SVG on desktop and mobile, and as text in the terminal
  (where `Svg` draws nothing).
- Colours come from `pomoPalette(findTheme(themeId))`, so the pane follows the
  theme.

## Review Focus

1. No source connected → the pane says "Connect Gmail, Slack or Calendar to
   start". Claude sessions still show.
2. The model reply isn't valid JSON, or is wrapped in a fence → `parseRanked`
   returns `[]`, keeps the last good list, and reports the error.
3. A source call throws or returns `isError` → that source is skipped and
   named in "couldn't read".
4. A dead session's `live:` entry → dropped once it is older than 6 h. A
   `working` entry older than 30 min reads as `idle`.
5. Two sessions open at once → only one fetches (by lease). The other shows
   the shared result.

### Task 1: Core logic (`hooks/needs-core.ts`)

**Files:** Create `hooks/needs-core.ts`. Test `tests/needs.test.tsx`.
Modify `types/index.d.ts`.

**Interfaces (Produces):**
- Types (in `types/index.d.ts`):
  - `NeedItem = { id, source, title, why, level: 'now'|'today'|'hidden', link?, at? }`
  - `NeedsResult = { items: NeedItem[], checkedAt: number, hash: string, failed: string[], error?: string }`
  - `LiveSession = { id, title, state: 'working'|'waiting'|'idle', at, note? }`
  - `Dismissed = Record<string, number>` (an id maps to the time it hides
    until; `Infinity` is stored as `0`, meaning done)
- `findSources(toolNames: string[]): FoundSource[]`, where `FoundSource = { kind: 'calendar'|'gmail'|'slack'|'upwork', server: string, tools: string[] }`.
  - Parses `mcp__<server>__<tool>`.
  - calendar = a server with `list_events`.
  - gmail = a server whose tools include `search_threads`, `list_messages` or
    `search_messages`, plus any `get_thread`/`get_message`.
  - slack = `slack_search_public_and_private` or `slack_search_public`.
  - upwork = `upwork__get_messages`.
- `rankPrompt(texts: { source: string, text: string }[], live: LiveSession[], now: number, vips: string[]): string`.
  This is the rules prompt. It asks for a JSON array of NeedItem only and
  includes the level rules verbatim.
- `parseRanked(reply: string): NeedItem[]`.
  - Strips a code fence and takes the first `[`…last `]`.
  - Drops entries missing id, title or level.
  - Clips the title to 80 characters and `why` to 60.
- `visible(items, dismissed, now, filter: 'all'|'now'): { shown: NeedItem[], hidden: number }`.
  - Order: now first, then today, then newest. Keep 7 at most.
  - Drop hidden-level items and dismissed ones. A dismissed item comes back
    when `dismissed[id] > 0 && dismissed[id] < now`.
- `liveItems(live: LiveSession[], selfId: string, now: number): NeedItem[]`.
  - A `waiting` session becomes `today`, with title `${title} is waiting for you`.
  - Drops entries older than 6 h and the session's own id.
- `canClaim(lease: { by: string, until: number } | undefined, me: string, now: number): boolean`
- `hashText(s: string): string` (FNV-1a, hex) and `ago(ms: number): string`
  (`just now`, `3 min ago`, `2 h ago`).

### Task 3: Sources and check (`hooks/needs-sources.ts`)

**Interfaces:**
- Consumes `findSources`, `rankPrompt`, `parseRanked`, `hashText` and
  `canClaim`.
- Produces `checkNeeds($: Api, opts: { me: string, force: boolean, vips: string[] }): Promise<NeedsResult | undefined>`.
  - Reads the store keys `needs-lease`, `needs-result` and every `live:*` key.
  - Returns `undefined` when another session holds the lease, unless `force`
    is set.
  - Otherwise it writes the lease for `{ by: me, until: now + 14 min }`.
  - It fetches each source, catching errors:
    - calendar: `list_events` with `startTime` = local now with no Z,
      `endTime` = +2 h, and `pageSize` 10.
    - gmail: the search tool with `{ query: 'is:unread in:inbox -category:promotions -category:social -category:updates newer_than:1d' }`.
    - slack: `{ query: 'to:me after:yesterday' }`, then a second search for
      `<@me>` mentions if the first returns nothing.
    - upwork: `list_accounts` → `org_uid`, then
      `get_messages {action:'list_rooms'}`.
  - Each source text is capped at 6000 characters.
  - It hashes the joined text. When the hash equals the last result's, it
    returns the old items with a new `checkedAt`.
  - Otherwise it calls `$.model.complete({ model: 'haiku', prompt })`. A
    `parseRanked` of `[]` from a non-empty source set keeps the old items and
    sets `error`.
  - It stores the result under `needs-result`.
- Arguments that the real tool schema contradicts are fixed at
  implementation: read the tool's description from `$.tool.list()`.

### Task 4: Pane, command, session reporter, wiring (`hooks/needs.tsx`)

**Interfaces:**
- Consumes everything above, plus `findTheme` and `pomoPalette`.
- Produces:
  - `startNeeds($, options)` and `registerNeeds(on)`, called from
    `register.tsx` the same way as Pomodoro.
  - Command `needs`: no args opens the pane, `check` forces a check.
  - Pane id `needs-pane`, title `Needs you`.
  - Atoms: `needsResult`, `needsDismissed`, `needsFilter`, `needsSelected`
    and `needsLive`. They are declared in `needs.tsx` and the contract.
- Behaviour:
  - At `session.start`, load the store into the atoms and start
    `$.clock.every(60_000)`. Each tick refreshes `needsLive` from the `live:*`
    keys. Every `interval` minutes (userConfig `needsInterval`, default 15) it
    calls `checkNeeds`.
  - A new `now` id that wasn't in the previous result triggers
    `$.ui.notify(title, { title: 'Needs you' })`.
  - Session reporter:
    - `turn.start` → store `live:<id>` with `{state:'working'}` and the cwd
      basename as the title.
    - `turn.complete` → `waiting` if the last assistant text ends with `?`,
      else `idle`.
    - `tool.check` → when `next(e)` resolves `decision: 'ask'`, `waiting`
      with the note `Asks to approve <tool>`.
    - `session.end` deletes `live:<id>`.
  - Desktop render:
    - The `summaryCard` Svg, then a row of Buttons: `needs-check`
      (primary, `↻ Check now`), `needs-all`, `needs-now` and `needs-vip` (⚙).
    - Then each item as `<Svg isInteractive onPress=select>`, with an
      `itemCard`.
    - Under the selected item: `Link href={link}` (`↗ Open`, only when there
      is a link), and Buttons `needs-done-<id>` and `needs-snooze-<id>`.
    - At the end, a footer Text: `N hidden: newsletters and notifications`,
      plus `couldn't read: …` when anything failed.
    - When no source is found: `Connect Gmail, Slack or Calendar to start`.
  - Terminal render: the same items as text lines with `●` coloured by level.
  - ⚙ opens an Input for comma-separated VIP names, stored under
    `needs-vips`.
  - plugin.json: add userConfig `openNeeds` (boolean, default true) and
    `needsInterval` (number, default 15), and bump the version to 1.4.0.
  - README: add a "Needs you" section with the commands, sources, rules, and
    the note about connecting Gmail and Slack.
